Active compression is the set of features that shrink content as it enters your context window, rather than after the fact. This page is the map; each feature has its own page with the full detail.

## What it covers

![Claude Code compression and signal features; optional gates have separate defaults](/images/active-compression-hero.svg)


The setup audit reduces the overhead you start a session with. Active compression reduces the overhead you accumulate during the session: redundant file re-reads, verbose command output, and large tool results that survive into compaction. Each feature targets one source of mid-session bloat and each is on by default where it is safe to be.

Several of these features are documented in depth on their own pages. This page exists so you can see them together, understand their defaults at a glance, and see which toggles `v5` manages.

## At a glance

| Feature | Default | Targets | Typical saving | Risk | Page |
|---|---|---|---|---|---|
| Read cache (delta mode) | On | Re-reading an unchanged or barely-changed file | A 2,000-token re-read becomes a 50-token diff | Low | [Read cache](/features/read-cache/) |
| Read cache (structure map) | On (soft-block) | Re-reading a large code file | A 720KB file becomes a 250-token skeleton | Low | [Read cache](/features/read-cache/) |
| Bash output compression | On | Verbose read-only CLI output | A 564-token pytest run becomes 115 tokens | Low | [Bash compression](/features/bash-compression/) |
| Search result compression | On | Long grep/search results | 500-line result becomes 20 lines + count | Low | [Bash compression](/features/bash-compression/) |
| Quality nudges | On | A sudden quality drop you should act on | A timely compact instead of a degraded context | None | [Quality signals](/features/quality-signals/) |
| Loop detection | On | The agent stuck retrying the same thing | Warning for repeated failures; no guaranteed loop termination | None | [Quality signals](/features/quality-signals/) |
| Lean-output nudges | On | Verbose model output at high context fill | Measured after a nudge when comparable later output is available; zero booked at firing | None | (this page) |

Two more features round out the nine, but they feed the compaction engine rather than shrinking content as it enters context, so they live on the [Quality signals](/features/quality-signals/) page: **Activity Mode** (classifies the session into one of five modes from the last ten tool calls, so compaction keeps what that phase needs) and **Decision Extraction** (carries the five most recent decisions across each compaction).

## How to manage the feature toggles

One command controls the runtime compression features as a group. The CLI verb is `v5` (a legacy name kept for compatibility — it controls current features, not a version).

```bash
cd ~/.claude/skills/token-optimizer/scripts

# Show the status of every active compression feature
python3 measure.py v5 status

# Turn one feature on or off
python3 measure.py v5 disable delta_mode
python3 measure.py v5 enable delta_mode

# Full detail for one feature
python3 measure.py v5 info delta_mode

# First-run welcome and summary
python3 measure.py v5 welcome
```

Feature names accepted by `enable` and `disable`: `bash_compress`, `delta_mode`, `structure_map_beta`, `quality_nudges`, `loop_detection`, `first_read_shadow`, `first_read_active`. Toggle state persists to `config.json`.

<Aside type="note">
You can also disable each feature with its own environment variable for a single run or in CI, without changing saved settings. The variables are listed per feature on the linked pages and defined once in the [configuration reference](/reference/configuration/).
</Aside>

## Default state

The main compression gates default on on Claude Code; structure-map beta event logging and tree-sitter are separate opt-ins. First-read serving is limited to promoted cohorts, where the PreToolUse and PostToolUse hooks can intercept tool calls. On platforms with reduced hook support, some features are approximated or unavailable; the [capability matrix](/reference/capability-matrix/) lists the per-platform reality.

## How to turn off

Turn off the whole behavior of one feature with its `v5 disable` verb above, or with its environment variable for a one-off. The two read-cache behaviors share `TOKEN_OPTIMIZER_READ_CACHE` (both off) and `TOKEN_OPTIMIZER_READ_CACHE_DELTA` (delta only). Bash compression uses `TOKEN_OPTIMIZER_BASH_COMPRESS`, which also gates search-result compression (there is no separate search variable). Quality nudges and loop detection use `TOKEN_OPTIMIZER_QUALITY_NUDGES` and `TOKEN_OPTIMIZER_LOOP_DETECTION`. Lean-output nudges are not a `v5` toggle. At 25-74% fill (floor tunable with `TOKEN_OPTIMIZER_VERBOSITY_MIN_FILL`) they require session efficiency below 75; at 75-89% fill the strong tier is eligible without that gate; at 90%+ no note is injected. They are capped at three per session with five minutes between notes. All are defined in the [configuration reference](/reference/configuration/).

## Risk rating

Low overall. Each compression feature fails open: when a substitution might lose information the model needs, the feature serves the full content instead. The two warning features (quality nudges, loop detection) only add a note for the model to read, so their risk is none. Per-feature failure modes are documented on each page.

## Related environment variables

`TOKEN_OPTIMIZER_BASH_COMPRESS`, `TOKEN_OPTIMIZER_READ_CACHE`, `TOKEN_OPTIMIZER_READ_CACHE_DELTA`, `TOKEN_OPTIMIZER_STRUCTURE_MAP`, `TOKEN_OPTIMIZER_QUALITY_NUDGES`, `TOKEN_OPTIMIZER_LOOP_DETECTION`. All defined in the [configuration reference](/reference/configuration/).

## Platform availability

Full suite on Claude Code CLI and VS Code. Hermes gets bash compression, delta and structure-map re-reads and loop detection through its output and tool hooks. Approximated or partial on Codex, Copilot, OpenClaw, and OpenCode depending on each platform's hook capabilities. See the [capability matrix](/reference/capability-matrix/).
