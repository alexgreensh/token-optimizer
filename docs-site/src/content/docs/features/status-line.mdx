The quality status line keeps three things in your Claude Code terminal that a single session view never shows together: how full the context window is, how well the context is actually being used right now, and, once there is a figure worth announcing, what Token Optimizer has saved you. You read them at a glance and compact at the right moment instead of guessing.

## What it does

![The live quality bar in the status line, colors shifting as context fills](/images/status-bar.svg)


The status line renders a compact two-row readout below your prompt. The first row shows your model, the effort level, the project directory and branch, a context-fill bar with a used percentage, and the context-quality grade. The second row leads with your savings headline when there is one worth showing, then a resumable-checkpoint mark when one exists, the biggest drag on the score, any active fill or tool-call warnings, the compaction count, the session duration, running agents, and your usage-limit windows.

```
Claude | med | my-project | (main) | ████████░░ 78% | Quality C 62
Saved $53/30d · 1.2M kept out ↗ | Drag:context fill | compacted 1× | 2h14m | 5 hours 61% ↺2:14p | week 34%
```

The savings headline is the same one number the desktop band and the dashboard Savings page show, so no surface quotes a different figure: this week's savings once they pass $20, otherwise the last 30 days from $60 with the tokens kept out of context, otherwise a tokens-only figure once a million tokens have been kept out, and nothing at all below those floors. It is read from the status-bar cache that `measure.py status-bar` writes, so the status line never spawns Python to get it, and in terminals with hyperlink support it is a clickable link to the dashboard's Savings page. The usage-limit fragments (the 5-hour window with its reset time, and the week) appear on Pro/Max accounts once the first API response of the session reports them, colored by pressure.

When the terminal reports its width (Claude Code v2.1.153+), each row's segments reflow onto as many physical lines as the width allows instead of being clipped. `TOKEN_OPTIMIZER_STATUS_BAR_SIZE=slim` collapses the whole thing to a single line: the first row, with the savings headline appended.

The fill bar is color-banded so a glance tells you the state: green under 50%, yellow to 70%, orange to 80%, and red above 80%. The quality grade runs from S (90+) down to F, and carries the same value-color so a low grade reads as a warning. A `~` prefix on the grade means the cached score is older than five minutes and may not be live.

The grade is the same context-quality score documented in [quality scoring](/concepts/quality-scoring/). The status line is how you watch it move without running a command.

## Where the numbers come from

Paths shown as `~/.claude/token-optimizer/` are legacy script-install paths. Plugin installs resolve state under their plugin-data identity; use the runtime's reported data directory rather than creating a second legacy copy.


The fill percentage comes from the data Claude Code hands the status line on every render. The quality grade comes from a small cache file that Token Optimizer's hooks keep updated.

A UserPromptSubmit hook recomputes the quality score on a roughly two-minute throttle and writes it to `~/.claude/token-optimizer/quality-cache-<session_id>.json`. The status line reads that file on each render. Because the cache is refreshed on a throttle rather than every keystroke, the status line applies a five-minute staleness guard: past that age it marks the grade with `~` rather than showing a frozen number as if it were live.

## Install and uninstall

`setup-quality-bar` installs the status line into `~/.claude/settings.json` and wires the quality-cache hook that feeds it.

<Steps>

1. Install the status line and its hook:

   ```bash
   cd ~/.claude/skills/token-optimizer/scripts
   python3 measure.py setup-quality-bar
   ```

2. Preview the change first, or check the current state, without writing:

   ```bash
   python3 measure.py setup-quality-bar --dry-run
   python3 measure.py setup-quality-bar --status
   ```

</Steps>

To remove it:

```bash
cd ~/.claude/skills/token-optimizer/scripts
python3 measure.py setup-quality-bar --uninstall
```

Uninstalling removes the status line and records a sticky opt-out (`quality_bar_disabled` in `config.json`) so it does not reappear on the next session start. Run `setup-quality-bar` again to clear the opt-out and reinstall.

<Aside type="note" title="It never overwrites a custom status line">
The auto-install only writes the status line when your `statusLine` slot is empty. If you already have a custom status line, Token Optimizer leaves it alone. To use the quality bar instead, clear your `statusLine` setting first, then run `setup-quality-bar`.
</Aside>

## Default state

On for plugin and marketplace users. The SessionStart `ensure-health` hook auto-installs the status line through `setup-quality-bar` when your `statusLine` slot is empty, and respects the `quality_bar_disabled` opt-out. Skill-only users install it once with the command above.

Platform availability: the terminal status line is a Claude Code surface. Codex has its own status-line command (`codex-status-line`). OpenClaw has no terminal status-line surface. See the [capability matrix](/reference/capability-matrix/).

## The /statusline clobber and auto-restore

Claude Code's `/statusline` command rewrites the `statusLine` setting, which replaces the quality bar with whatever it generates. How Token Optimizer responds depends on how you installed it.

For **skill-only** installs, the status line is restored: the next SessionStart `ensure-health` detects that the slot no longer holds the quality bar and reinstalls it, unless you have set the opt-out.

For **plugin** installs, there is no auto-restore after `/statusline` clobbers the bar. Claude Code exposes no signal that distinguishes an accidental clobber from a status line you chose on purpose, so the plugin does not second-guess your choice. This is a deliberate, accepted trade-off. To get the quality bar back after `/statusline` replaces it, run `setup-quality-bar` again.

<Aside type="caution" title="Plugin users">
If you run `/statusline` and lose the quality bar, reinstall it with `python3 measure.py setup-quality-bar`. The plugin will not restore it automatically.
</Aside>

## Reading the cache from a custom status line

If you maintain your own status line and want the quality grade in it, read the cache file directly. Token Optimizer writes the per-session score to:

```
~/.claude/token-optimizer/quality-cache-<session_id>.json
```

The file holds the score under `resource_health` (falling back to `score`), a letter grade under `resource_health_grade` (falling back to `grade`), and a session-efficiency score under `session_efficiency`. Apply your own staleness check against the file's timestamp; the bundled status line treats a score older than five minutes as stale. The quality-cache hook keeps the file current as long as Token Optimizer is installed, so a custom status line gets the same live grade without running any Token Optimizer command itself.

## When it updates

Automatically. The fill bar updates on every status-line render. The quality grade updates whenever the quality-cache hook runs, which is on UserPromptSubmit (throttled to about two minutes) and after tool use, with a force-refresh on SessionStart and after compaction.

## Defaults and thresholds

| Setting | Default | Notes |
|---|---|---|
| Layout | two rows | Row 1: model, effort, project, branch, fill + quality grade. Row 2: savings headline, resumable mark, drag, warnings, compacts, duration, agents, limits |
| Fill color bands | under 50 green, under 70 yellow, under 80 orange, 80+ red | On the used percentage |
| Quality grades | S 90+, A 80+, B 70+, C 55+, D 40+, F below | Same score as quality scoring |
| Staleness mark | `~` after 5 minutes | Cache older than the guard window |
| Savings headline floors | $20 this week, else $60 over 30 days, else 1M tokens | Below every floor the headline shows nothing |
| Narrow terminals | Reflow to fit | When the host exports `COLUMNS`; `TOKEN_OPTIMIZER_STATUS_BAR_SIZE=slim` forces one line |
| Quality-cache refresh | ~2-minute throttle | On UserPromptSubmit and PostToolUse |
| Auto-install | on (plugin) | When `statusLine` slot is empty |
| Opt-out | `quality_bar_disabled` | Set by `--uninstall`, sticky |

## The desktop status bar

The terminal status line above has a sibling for the Claude desktop app. Token Optimizer draws a status bar above your prompt: one sentence about the most urgent thing, with at most one button, then five marks (quality grade, context fill, cache countdown, 5-hour limit, weekly limit) that open a card on hover. The arrow beside Clawd unfolds branch, session time, tool calls, compactions, the last checkpoint, and the tokens Token Optimizer saved you in the last 30 days, ending with a **Full dashboard** link that opens the dashboard in your browser. Clawd acts out what the session is doing, from thinking and typing to compacting, a cold cache, or napping.

Buttons: **Clean up** compacts with Token Optimizer's guidance. **Start fresh** asks for a second click, then saves a checkpoint, clears, and hands the checkpoint to your first message. **Keep warm** is a manual cache refresh, covered in [Keep-Warm](/features/keep-warm/#the-manual-keep-warm-button).

The cache countdown prefers Claude Code's native `prompt_cache` object (v2.1.251+), bridged by the terminal status line: TTL, expiry, and warm/cold state describe the main conversation, not subagents. When that bridge is unavailable, it falls back to a transcript-based estimate: 1 hour on Claude plans or 5 minutes on the API. Native and estimated sources are distinguished; no countdown is shown without an anchor. Use the -/+ size control for a remembered one-line/full choice, or `TOKEN_OPTIMIZER_STATUS_BAR_SIZE=slim` for the initial desktop and terminal size. Hide the bar with `TOKEN_OPTIMIZER_STATUS_BAR=0`, or keep Clawd still with `TOKEN_OPTIMIZER_STATUS_BAR_ANIMATE=0`, in your settings `env`. Install steps and requirements are in [Claude desktop app](/install/claude-desktop/).

## Risk rating

**Terminal status line: none.** It only displays, and installing it only writes the `statusLine` setting (and only when the slot is empty). A missing or stale cache shows `--` or a `~`-marked grade, never a wrong action.

**Desktop status bar: low.** Its buttons act only when you press them, and Start fresh asks for a second click first. Nothing runs on its own.

## Related environment variables

The status line is installed and removed by the `setup-quality-bar` command and the `quality_bar_disabled` config key, both defined in the [configuration reference](/reference/configuration/). One environment variable shapes it directly: `TOKEN_OPTIMIZER_STATUS_BAR_SIZE=slim` forces the single-line layout described above.

## Platform availability

Claude Code CLI and VS Code. Codex uses `codex-status-line`. OpenClaw has no terminal status-line surface. See the [capability matrix](/reference/capability-matrix/).
