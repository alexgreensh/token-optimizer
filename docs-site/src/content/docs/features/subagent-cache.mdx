Subagents always get the short prompt cache. On a subscription your main conversation caches for an hour, but every subagent prefix expires after five minutes, so a subagent you return to, or the same agent type spawned again, rewrites its whole prefix after a short break. Claude Code 2.1.243+ exposes `subagentPromptCacheTtl`, a settings key that raises the subagent TTL to one hour, the same window the rest of the plan gets.

## What it does

Token Optimizer turns on `"subagentPromptCacheTtl": "1h"` in your **user** `settings.json` when your own history shows it pays, once, and only when it is also safe. The first time it writes, one line tells you it happened, what your last 30 days would have saved, and how to undo it; every session after that is a silent no-op.

A 1-hour cache is not free. Writing a prefix at 1 hour costs 2x the base input price instead of 1.25x, so it only wins when subagents are returned to, or respawned, within the hour. A heavy subagent user measured roughly break-even; a user whose subagents run once would lose money. That is why the automatic path is gated on evidence.

## When it turns on

At session start Token Optimizer reads one small cached verdict about your last 30 days. It sets the key only when both hold:

- **Enough data.** At least 200 subagent requests in the window. Below that the decision is "not enough data".
- **It pays.** The estimated saving is at least 1.15 times the estimated 1-hour write premium. The 15% margin keeps a coin-flip from changing a setting you never asked about.

Otherwise it writes nothing and records why, with a timestamp, in its marker: "not enough data" or "would not pay: saved $X vs premium $Y". It is re-judged at most once a day, and `subagent-cache status`, `doctor`, `quick` and `coach --json` all show the decision and its reason (`auto_decision`).

The scan that produces the verdict walks your transcripts, which can take several seconds, so it never runs inside session start. When there is no verdict, or it is more than a day old, session start launches the scan as a detached background process (no console window on Windows, one scan at a time, bounded by a time budget and a file cap) and carries on. A scan that hits either bound is partial and produces no verdict. The result is applied at a later session start.

Two switches override the evidence check:

- `TOKEN_OPTIMIZER_SUBAGENT_CACHE_1H=1` (also `true`, `on`, `yes`): always on. The automatic path enables without the evidence check, and every safety rule below still applies.
- `subagent-cache enable`: the manual command. It prints your estimate first, then enables unconditionally.

The safety rules, in order:

- **Your value wins.** If the key already exists with any value (including `"5m"`) it is treated as yours and never touched.
- **Environment wins.** `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` or `FORCE_PROMPT_CACHING_5M` set means do nothing; the env outranks the setting anyway.
- **Other settings files win.** A managed, project, or local `settings.json` that already sets the key outranks the user file, so Token Optimizer does nothing and reports which file answered.
- **Version floor.** Requires Claude Code 2.1.243 or newer; anything older or undetectable is skipped.
- **Declines are remembered.** If you remove or change the key after Token Optimizer set it, a marker records the decline and the automatic path never sets it again.
- **Unknown means no.** Unreadable, missing, or malformed settings are never written.
- **Never.** `TOKEN_OPTIMIZER_SUBAGENT_CACHE_1H=0` (also `false`, `off`, `no`) blocks the set entirely, and if the setting was already applied, it is removed.

A marker in Token Optimizer's own data directory (timestamp plus previous state) is how `disable` knows what it may undo: the key is removed only when the marker says Token Optimizer set it and the value is still `"1h"`. Your uninstall path calls the same undo.

## The payoff check

`subagent-cache status` judges the feature on your own transcripts, not a hypothetical. For the last 30 days it adds up two kinds of avoided rewrite and charges the 1-hour write premium against them:

- **Within one agent.** A request in a subagent transcript that follows the previous one by 5 to 60 minutes rewrote at 5m what a 1h cache would have read.
- **Across spawns.** The bigger win. The same agent type started again 5 to 60 minutes later rewrites its shared prefix (system prompt plus tool definitions) at 5m, and would read it at 1h. Spawns are grouped by project, agent type (when the transcript's `.meta.json` records one) and model; without a recorded agent type the group is project and model, and `status` says so. The shared prefix is the smallest first request across the group's spawns, so a group needs two or more spawns before it earns anything.

Once the setting is on, writes are 1h writes, so the same two numbers are read from what actually happened: the premium really paid on the 1h writes, and the cache reads that followed a 5 to 60 minute gap (reads that would have been 5m writes). One history can mix both regimes. The two parts are reported separately, a request is never counted twice, and subscription plans see tokens first with the dollar figure labelled API-equivalent. It is always an estimate.

```bash
cd ~/.claude/skills/token-optimizer/scripts
python3 measure.py subagent-cache status          # state, the automatic decision and why, net estimate
python3 measure.py subagent-cache status --json   # machine-readable
python3 measure.py subagent-cache enable          # set it now: prints your estimate, then enables
python3 measure.py subagent-cache disable         # undo (only what Token Optimizer set)
```

### The tripwire

If 14 or more days of post-enable data show a **negative** net estimate (the 1h write premium outweighing the rewrites it avoided), **and** the window holds at least 200 subagent requests, the next session start removes the key (only when Token Optimizer set it), records `auto-reverted`, and says so in one line. It judges the same kind of cached verdict, for the post-enable window, produced by the same background scan. It is re-judged at most once a day so the steady-state session start stays cheap. An explicit `subagent-cache enable` clears the auto-revert state.

<Aside type="note" title="Estimate, not metered savings">
The payoff figure is deterministic math over your transcripts (request timestamps and cache-creation fields), not metered billing data. Reads are credited only in the 5 to 60 minute gap band, and every write is charged the full 1h premium. With fewer than 200 subagent requests in the window the check says "not enough data" and never reverts.
</Aside>

## Default state

On for Claude Code 2.1.243+ when your own history shows it pays, applied once at a session start. Cowork and every other runtime are a clean no-op. The feature never reads or writes `~/.claude` outside Claude Code.

## How to turn it off

```bash
python3 measure.py subagent-cache disable
```

or permanently, in your environment or `settings.json` `env` block:

```bash
TOKEN_OPTIMIZER_SUBAGENT_CACHE_1H=0   # never
TOKEN_OPTIMIZER_SUBAGENT_CACHE_1H=1   # always on, no evidence check
```

`disable` removes the key only when the marker says Token Optimizer set it. If you set the key yourself, it is left alone.

## Defaults and thresholds

| Setting | Default | Notes |
|---|---|---|
| Feature state | evidence-gated (Claude Code 2.1.243+) | Set once, at a session start after the verdict says it pays |
| Auto-enable minimum sample | 200 subagent requests in 30 days | Below it: "not enough data", no write |
| Auto-enable margin | saving at least 1.15x the 1h premium | Otherwise: "would not pay: saved $X vs premium $Y" |
| Verdict cache | 24 hours | Older or missing: detached background scan, applied at a later session |
| Scan bounds | 120 s, 20,000 files | Hitting either is a partial scan: no verdict |
| Value written | `subagentPromptCacheTtl: "1h"` | User `settings.json` only |
| Tripwire window | 14 days of post-enable data | Negative net estimate reverts |
| Tripwire minimum sample | 200 subagent requests | Below it: "not enough data", no revert |
| Tripwire re-judge | once per 24 hours | Verdict stands between checks |
| Payoff lookback | 30 days | `status` reports tokens and dollars, estimated |
| Never | `TOKEN_OPTIMIZER_SUBAGENT_CACHE_1H=0` | Also `false`, `off`, `no` |
| Always on | `TOKEN_OPTIMIZER_SUBAGENT_CACHE_1H=1` | Also `true`, `on`, `yes`; skips the evidence check only |

## Risk rating

Low. One settings key, set once and only when your own history shows it pays, with every override path (user value, env, managed/project/local files) taking precedence over the write. The undo is exact: it only removes what Token Optimizer set, and the tripwire reverts automatically if the economics go negative. Failures fail closed: unknown-state settings are never written.

## Related environment variables

- `TOKEN_OPTIMIZER_SUBAGENT_CACHE_1H`: `0`, `false`, `off`, `no` for never; `1`, `true`, `on`, `yes` for always on; unset for evidence-gated
- `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`: Claude Code's own override; outranks the setting
- `FORCE_PROMPT_CACHING_5M`: forces the 5-minute cache everywhere; blocks the set

See the [configuration reference](/reference/configuration/).

## Platform availability

Claude Code 2.1.243+ only, on macOS, Linux, and Windows (the managed-settings path is platform-aware). Codex, Cowork, OpenCode, Cursor, Hermes, Copilot, and Antigravity are clean no-ops. See the [capability matrix](/reference/capability-matrix/).
