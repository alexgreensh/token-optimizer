The Token Optimizer plugin adds a status bar above the prompt in the Claude desktop app. It shows session quality, context, cache and limits at a glance, and puts Clean up, Start fresh and Keep warm one click away.

## Prerequisites

- The Token Optimizer plugin (see [Claude Code (CLI)](/install/claude-code-cli/)). The status bar is part of it.
- Claude Code 2.1.287 or newer.
- Anthropic's mods feature. Anthropic can switch it off remotely. When it is off, nothing breaks and the bar simply does not appear.

## Install

Nothing extra. Install or update the Token Optimizer plugin and open a new session in the desktop app; the bar appears above the prompt.

<Aside>
If you installed the separate `token-optimizer-desktop` plugin from an earlier release, remove it so only one bar shows: `/plugin uninstall token-optimizer-desktop@alexgreensh-token-optimizer`.
</Aside>

## What it shows

- One sentence about the most urgent thing, with at most one button.
- Five marks: quality grade, context fill, cache countdown, 5-hour limit, weekly limit. Hover any mark for a card.
- The **arrow beside Clawd** unfolds one more line: branch, session time, tool calls, compactions (when any), when the last checkpoint was saved (any kind, or a relevant one from an earlier session), and the tokens Token Optimizer saved you in the last 30 days, the same total the dashboard shows.
- Clawd acts out what the session is doing: thinking, reading, typing, subagents, waiting for your permission, writing, compacting, done, stopped, API error, cold cache, napping.

## Full dashboard

With the line unfolded (the arrow beside Clawd), the last thing on it is a plain text link, **Full dashboard**, in both the full and the slim band. The folded band does not show it. A click regenerates the Token Optimizer dashboard and opens it in your default browser, the same as the `token-dashboard` skill. While it runs the band says "Opening the dashboard."; if it cannot, it says "Could not open the dashboard." for a few seconds and nothing else happens. Clicking again while it is still opening is ignored.

## Buttons

- **Clean up** compacts with Token Optimizer's guidance, the same as typing `/compact`.
- **Start fresh** asks for a second click, then saves a checkpoint, clears, and hands the checkpoint to your first message.
- **Keep warm** is a manual, one-click cache refresh. It is offered only while the cache is still warm and its lifetime has been measured. It never runs on its own, disappears when the cache expires, and uses a small amount of your usage. Afterwards it tells you how many tokens it re-read from the cache and that the countdown is back to full. It is separate from the [Keep-Warm daemon](/features/keep-warm/#the-manual-keep-warm-button).

## The cache countdown

The countdown prefers the native Claude Code `prompt_cache` object when bridged by the terminal status line (v2.1.251+). Otherwise it falls back to a session-anchored estimate: 1 hour on Claude plans or 5 minutes on the API. Native cache state covers the main conversation, not subagents.

## Settings

Three switches, set in the `env` block of `~/.claude/settings.json` like the other Token Optimizer switches:

- `"TOKEN_OPTIMIZER_STATUS_BAR": "0"` hides the bar.
- `"TOKEN_OPTIMIZER_STATUS_BAR_ANIMATE": "0"` keeps Clawd still.
- `"TOKEN_OPTIMIZER_STATUS_BAR_SIZE": "slim"` starts the band as one line instead of the full band. The `–` button beside the arrow shrinks it and `+` brings it back. The arrow still unfolds the details row under it, and the choice is remembered across sessions and restarts.

## The "hook was skipped" notice on managed machines

On a machine with managed settings, or a Team or Enterprise login, Claude Code seats a built-in guard (`cc-plugin-sec-default`) ahead of every plugin you install. The guard sends every settings-hook event (`classic.*`) past installed plugins, so those handlers never run. Claude Code then tells you once per session and event:

> token-optimizer: its classic.SessionStart hook was skipped. "cc-plugin-sec-default" runs first and sent the event on past it.

Both parts are Claude Code behavior: the guard's rule is in [its public source](https://github.com/anthropics/claude-code/blob/main/mods/sec-default/hooks/register.ts) and the notice is raised by Claude Code. An organization cannot reorder a plugin installed from a marketplace ahead of the guard, so Token Optimizer cannot move itself either.

Token Optimizer registers two settings-hook handlers and no others, so you see at most two of these notices: `classic.SessionStart` at the start of a session, and `classic.PermissionRequest` the first time Claude asks for a permission.

What the skipped handlers cost the status bar, read from the module's code:

- **`classic.SessionStart`**: after `/clear`, the bar does not learn the new session id from this event, so it can keep the old session's figures until its next refresh. Start fresh's hand-off still reaches your first message. The transcript path it carries is an optional hint; without it Token Optimizer looks the session up by id.
- **`classic.PermissionRequest`**: Clawd does not switch to "waiting for your permission".

Your hooks in `hooks.json` (compression, checkpoints, quality scoring) are a separate path and keep running. Neither handler can be dropped without losing these behaviors on machines with no guard, and Claude Code lets a plugin register hooks only while it loads, so a plugin cannot register them only when the guard is absent.

## Where it works

The Claude desktop app only. The terminal keeps its existing [status line](/features/status-line/). VS Code is not supported.

## Turning it off

Add `"TOKEN_OPTIMIZER_STATUS_BAR": "0"` to the `env` block of `~/.claude/settings.json` and start a new session. The rest of Token Optimizer keeps working.
