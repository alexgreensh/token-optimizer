Codex runs the Token Optimizer engine through its own hook API. Quality scoring, cost tracking, the dashboard, and session continuity all work. A few Claude Code features are approximated or unavailable because the Codex hook API exposes less than Claude Code's, and each gap is named below with its upstream cause.

Codex CLI and Codex Desktop share one adapter. There is no separate Desktop install. The `aggressive` default includes silent Bash PostToolUse bookkeeping; `telemetry` installs only that bookkeeping and Stop. Neither profile promises visible Desktop rows.

## Supported surfaces

- **Codex CLI** is the primary surface.
- **Codex Desktop** loads the same `~/.codex/hooks.json` and behaves identically.

Install from the [Codex (CLI)](/install/codex-cli/) or [Codex (Desktop)](/install/codex-desktop/) page. The full capability grid is at [/reference/capability-matrix/](/reference/capability-matrix/).

## Runtime prefix

Every Token Optimizer command on Codex carries the runtime prefix:

```bash
TOKEN_OPTIMIZER_RUNTIME=codex python3 skills/token-optimizer/scripts/measure.py <command>
```

This selects the Codex adapter, the Codex dashboard port, and Codex pricing. Omitting it falls back to the Claude Code defaults.

## How Codex maps to Claude Code

Codex uses different config and memory conventions, and the adapter follows them.

| Concept | Claude Code | Codex |
|---|---|---|
| Config file | `CLAUDE.md` | `AGENTS.md` |
| Memory system | `MEMORY.md` plus project memory dirs | `~/.codex/memories/**/*.md` |
| Model routing advice | Opus, Sonnet, Haiku per agent | Intelligence levels plus GPT-5.x model selection |
| Hook install | Auto on plugin install, 11 events | `codex-install` command, global by default, 4 profiles, 1 to 6 events before optional flags |
| Compact lifecycle | PreCompact and PostCompact capture and restore | Compact-prompt guidance plus Stop checkpoints |
| Tool result archive | PostToolUse archives immediately | Stop-time backfill from JSONL, plus Bash PostToolUse on telemetry/aggressive profiles |
| Dashboard refresh | SessionEnd hook plus daemon at 24842 | Stop hook plus daemon at 24843 |

The Token Coach reads `AGENTS.md` and the Codex memory directories, and its routing advice speaks in GPT-5.x intelligence levels and model choices rather than the Claude model tiers.

## Hook profiles

Codex hooks install through `codex-install`. The default is `aggressive`; profiles select event coverage, not visible Desktop noise. Compact-prompt guidance is installed separately on every profile unless you pass `--skip-compact-prompt`.

Bash command rewriting remains off on every profile. Add `--enable-bash-compression` to install a Bash PreToolUse hook; it uses `updatedInput` and is inert on builds that ignore that field. `--enable-prompt-hooks`, `--enable-hot-path-hooks`, and `--enable-subagent-hooks` add coverage to a smaller profile; `--no-subagent-hooks` omits subagent hooks even on balanced/aggressive.

| Profile | Events installed | Behavior |
|---|---|---|
| `aggressive` (default) | SessionStart, UserPromptSubmit, SubagentStart, SubagentStop, PostToolUse (Bash), Stop | Silent by default, 6 events |
| `balanced` | SessionStart, UserPromptSubmit, SubagentStart, SubagentStop, Stop | 5 events |
| `quiet` | Stop | 1 event |
| `telemetry` | PostToolUse (Bash), Stop | Silent bookkeeping, 2 events |

```bash
TOKEN_OPTIMIZER_RUNTIME=codex python3 skills/token-optimizer/scripts/measure.py codex-install --profile quiet
```

## What is approximated

| Feature | Behavior on Codex | Upstream cause |
|---|---|---|
| Smart Compaction | Approximated through compact-prompt guidance plus Stop checkpoints | No PreCompact or PostCompact hook in Codex |
| Crash recovery | Approximated with Stop plus the compact prompt | No StopFailure hook in Codex |
| Bash output compression | Experimental opt-in only | Command rewriting requires explicit `--enable-bash-compression`; host must honor `updatedInput` |
| Cache-write TTL breakdown | Cached input shown, no 1h or 5m split | Codex logs do not expose cache-write TTL fields |
| Skill usage telemetry | Partial, from limited log signals | Codex logs do not expose every skill invocation event |

## What is unavailable

| Feature | Upstream cause |
|---|---|
| Delta read substitution | Codex PreToolUse Read hook does not support `updatedInput` |
| Structure-map substitution | Same `updatedInput` gap |
| Keep-Warm automation | See below |

<Aside type="caution">
Keep-Warm does not apply to Codex. OpenAI caching is automatic, so there is no cache-write premium to recover, and `codex exec resume` appends to a session rather than forking it. The savings model that justifies Keep-Warm on Claude Code does not exist here.
</Aside>

## Dashboard

The Codex dashboard serves at `http://localhost:24843/token-optimizer`. The Claude Code dashboard on 24842 can run at the same time without conflict. The file fallback lives at `~/.codex/_backups/token-optimizer/dashboard.html`.

```bash
TOKEN_OPTIMIZER_RUNTIME=codex python3 skills/token-optimizer/scripts/measure.py setup-daemon
```

For LAN access, set `TOKEN_OPTIMIZER_DASHBOARD_HOST=0.0.0.0` before `setup-daemon`. The setting is sticky and independent per runtime.
