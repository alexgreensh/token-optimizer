Token Optimizer supports the surfaces in the grid below and the separately scoped Grok Build, Pi, and Cowork adapters. Feature coverage varies because each host exposes a different hook surface. The grid below shows exactly what works where. The full feature set lands on Claude Code; other platforms cover what their host APIs allow.

Legend: **Yes** = full support, **Part** = partial or capability-gated, **Beta** = beta status, **No** = not available, **n/a** = not applicable, **verify** = not confirmed in source.

## How to read the gaps

The repeated **No** entries fall into a few clear groups.

**Read interception (delta and structure map)** needs a hook that can rewrite the result of a file read before the model sees it. Claude Code supports this; Codex lacks `updatedInput` on its Read hook; Copilot's `additionalContext` on `preToolUse` is broken upstream in Copilot CLI. Cursor, OpenCode and OpenClaw have no equivalent hook in their APIs. Antigravity's `PreToolUse` can overwrite what is about to be read but cannot rewrite the tool result, so the substitution features are unavailable there too. Hermes's `pre_tool_call` can answer a read itself, so delta and structure-map reads work there.

**Bash output compression** needs a hook that can rewrite tool input silently. Available on Claude Code, Cursor (every Shell rewrite is recorded as `honoured` or `ignored`), and Antigravity (whose rewritten command is re-validated by the wrapper before execution), experimental opt-in on Codex, gated on a Copilot CLI version, and unavailable on the TypeScript platforms. Hermes compresses the captured output through its `transform_terminal_output` hook, so every command is covered without rewriting what runs. On Claude Code, build and test commands (gcc, cargo, npm, make, go, mvn, and more) are also compressed PostToolUse even when they are not read-only: the command already ran, so the hook collapses repetition in the captured output while preserving every distinct error line, exit status, and summary.

**Quality Nudges and Loop Detection** need a session-visible notification surface to inject a warning the model can act on. Claude Code has it via `UserPromptSubmit`; Cursor's `postToolUse` context surface fires on a tool-call-count proxy when `preCompact` has not supplied real context numbers. OpenCode appends native warnings through its system-transform path; OpenClaw does not carry these shared nudges. Hermes exposes `pre_llm_call` for nudges and returns loop warnings with the terminal output itself.

**Status line** needs a host status surface. Claude Code has it (and the VS Code VSIX surfaces it in the editor). Codex CLI has an explicit `--enable-status-line` installer option; that does not add the Claude desktop status bar to Codex Desktop.

**Keep-Warm** watcher/reporting is Claude Code-oriented; the scheduler is macOS-only and production LLM pings are disabled. The modeled automatic path normally requires API billing. OpenAI caching is automatic with no cache-write premium to recover; the other hosts have no comparable lever.

**Cost tracking** is absent on Cursor because the host exposes no billing figure to hooks or state files. The adapter surfaces `cursor_no_cost_data` rather than inventing a dollar number.

**OpenClaw extras** (read-cache warn/block, git-aware context, drift, impact validation, agent cost breakdown, model-switch simulation) are features of the native OpenClaw TypeScript engine. The Python CLI also ships `git-context`, `drift`, and `validate-impact`, and its Read hook supports warn/block modes. These are shared CLI or hook capabilities, not proof of parity with every OpenClaw dashboard simulation.

## Quality scoring depth

Where a platform exposes 7 signals, the score uses the full set: context-fill degradation, stale reads, bloated results, duplicate system reminders, compaction depth, decision density, and agent-dispatch efficiency. Hermes, Copilot, Cursor, and Antigravity fall back to a 3-signal subset because their session schemas do not persist the other signals reliably. The S/A/B/C/D/F grade scale is identical everywhere, so grades are comparable across platforms even when the underlying signal count differs.

## Claude Cowork

Cowork is not shown as a column above. It runs the same Claude Code engine in a VM rather than exposing its own hook API, so its feature coverage is that of Claude Code minus the events omitted from the packaged Cowork payload (`SessionStart`, `PreCompact`, `PostCompact`, `SessionEnd`, `StopFailure`, `PostToolUseFailure`, `CwdChanged`). The adapter is experimental and its hook firing is not yet confirmed on a live build, so a per-cell grid would overstate what has been verified. The [Cowork page](/platforms/cowork/) lists the intended hook set, what works, what is degraded (in-place compaction restore), and what is not measurable from inside a Cowork session.
