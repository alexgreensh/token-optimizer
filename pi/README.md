# Token Optimizer for Pi

The Git-source install below has not been tested end to end. Install with `pi install git:github.com/alexgreensh/token-optimizer` or test a local checkout with `pi install ./pi`. Update with `pi update --extensions`. Uninstall with `pi remove git:github.com/alexgreensh/token-optimizer` (or `pi remove ./pi` for the local source). The root manifest loads only the Pi extension and does not auto-load the other runtime skills. Project-local installations require Pi's project trust.

Run `/token-optimizer` for status, `/token-optimizer doctor` for runtime diagnostics, and `/token-optimizer enable` to opt in to local measurement. The extension is off by default. Its isolated data directory is `~/.pi/agent/token-optimizer` (override with `TOKEN_OPTIMIZER_PI_HOME`). `/token-optimizer disable` stops measurement. `/token-optimizer continuity on` separately opts in to storing redacted goal markers and showing them as review candidates after native Pi compaction; review with `/token-optimizer continuity candidates` and opt in to reinjection with `/token-optimizer continuity accept`. This does not replace Pi's model or native compaction; accepted continuity candidates do alter the model context.

Local model-level usage is read from the active Pi branch, and native Pi costs are reported without invented savings. Tool-output archives are separately opt-in with `/token-optimizer archive on`. This stores full redacted results up to 64 KiB each and approximately 10 MiB total (best-effort across concurrent Pi processes); unknown secret formats may escape screening, so avoid enabling it for sensitive outputs. The agent still sees full tool results: no trimming occurs. `/token-optimizer archives` lists recent recovery pointers, and `/token-optimizer recover POINTER` displays a redacted result. Archives and checkpoints are retained after disabling until pruning runs (default seven days) or you run `/token-optimizer purge all`. Purge deletes the extension-managed files, not Pi session history. The extension does not replace native compaction.

Tests use synthetic Pi session entries and an RPC extension-load smoke test. Live native compaction lifecycle and live model inference have not been verified. Cost coverage is shown separately for native, estimated, and unpriced calls; the native figure is a subtotal, not a complete bill.
